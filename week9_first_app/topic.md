# DailyTodo — 9주차 최종 주제 정리

## 1. 주제 및 확인 상태

- **앱 이름:** DailyTodo
- **주제:** 오늘 해야 할 일을 간단히 등록하고 완료 여부를 관리하는 할 일 관리 앱
- **주제 확인 상태:** 검토안 — 교수님 미확인
- **앱 구현 상태:** 구현 전
- **앱 AC 상태:** 미실행

> 교수님에게 최종 확인받았다는 정보가 아직 문서에 제공되지 않았으므로 미확인으로 기록한다. 수업에서 확인받은 뒤 상태와 피드백을 직접 수정한다.

## 2. 사용자와 해결하려는 문제

- **대상 사용자:** 하루 동안 해야 할 일을 간단하게 정리하고 싶은 학생
- **문제:** 해야 할 일이 메모나 여러 곳에 흩어지면 오늘 해야 할 일을 한눈에 확인하기 어렵고, 어떤 일을 끝냈는지 구분하기 어렵다.
- **해결 목표:** 오늘의 할 일을 한 화면에 모아 등록하고, 완료 여부를 표시해 남은 일을 쉽게 확인한다.

## 3. 선택 이유

DailyTodo는 추가·목록 확인·완료 표시라는 작은 핵심 흐름이 분명하다. 기능 범위를 작게 유지할 수 있고, 입력값과 목록 데이터 및 완료 상태의 변화를 화면에서 직접 확인할 수 있다. 따라서 10주차에 기본 화면과 핵심 행동부터 구현하고 AC에 따라 단계적으로 확인하기 적합하다.

## 4. 핵심 사용자 흐름

1. 사용자가 DailyTodo를 실행한다.
2. 오늘의 할 일 목록과 입력란을 확인한다.
3. 할 일 제목을 입력하고 추가 버튼을 누른다.
4. 입력한 할 일이 목록에 한 번 표시된다.
5. 할 일을 끝내면 해당 항목의 완료 표시를 누른다.
6. 선택한 항목만 완료 상태로 바뀐다.

## 5. 기능 범위

### 필수 기능

- 할 일 제목 입력
- 빈 제목 입력 거절 및 안내
- 할 일 추가
- 오늘의 할 일 목록 표시
- 항목별 완료/미완료 상태 전환
- 등록된 항목이 없는 경우 빈 목록 안내 표시

### 이번 버전에서 제외할 기능

- 회원가입 및 로그인
- 서버·클라우드 동기화
- 여러 기기 간 데이터 동기화
- 푸시 알림 및 반복 일정
- 카테고리, 태그, 우선순위, 통계 기능
- 앱 재실행 후에도 데이터가 유지되는 영구 저장

제외 기능은 핵심 흐름을 먼저 구현하기 위해 이번 MVP 범위에서 보류한다.

## 6. 데이터와 저장 방식

| 항목 | 설계 |
|---|---|
| 할 일 식별자 | `id` |
| 제목 | `title` |
| 완료 여부 | `isDone` |
| 저장 범위 | 앱 실행 중 메모리 |
| 서버 사용 | 사용하지 않음 |
| 개인정보 | 개인 식별 정보나 계정 정보를 수집하지 않음 |

앱을 종료하거나 재실행하면 목록이 유지되지 않는 것을 이번 버전의 제약으로 명시한다. 따라서 문서에서 말하는 목록 관리는 앱 실행 중의 관리이며, 재실행 후 영구 보존을 의미하지 않는다.

## 7. 화면 스케치

```text
┌──────────────────────────────┐
│          DailyTodo           │
│        오늘의 할 일           │
├──────────────────────────────┤
│ [ 할 일을 입력하세요       ] │
│                         [추가]│
├──────────────────────────────┤
│ □ 과제 자료 정리              │
│ ☑ 강의 복습하기               │
│ □ 운동하기                    │
├──────────────────────────────┤
│ 남은 할 일: 2개               │
└──────────────────────────────┘
```

- 입력란과 추가 버튼으로 새 할 일을 등록한다.
- 목록의 체크 표시로 각 항목의 완료 여부를 바꾼다.
- 위 스케치는 구현 전 계획이며 실제 앱 화면이나 실행 증거가 아니다.

## 8. 앱 수용 조건(AC)

| ID | 시작 상태 / 행동 | 기대 결과 | 확인 방법 | 상태 |
|---|---|---|---|---|
| AC1 정상 추가 | 앱에서 제목 `과제하기`를 입력하고 추가 버튼을 한 번 누른다. | 목록에 `과제하기` 항목이 한 개 추가된다. | 실행 화면에서 항목 수와 제목 확인 | 미실행 |
| AC2 빈 제목 | 입력란을 비워 두거나 공백만 입력하고 추가 버튼을 누른다. | 항목이 추가되지 않고 입력이 필요하다는 안내가 표시된다. | 실행 화면에서 목록이 그대로인지와 안내 확인 | 미실행 |
| AC3 완료 전환 | 미완료 항목 하나의 완료 표시를 누른다. | 선택한 항목만 완료 상태로 바뀌고 다른 항목은 유지된다. | 누르기 전후 화면 비교 | 미실행 |
| AC4 빈 목록 | 등록된 할 일이 없는 상태로 첫 화면을 연다. | 빈 목록임을 알려주는 안내가 표시된다. | 항목이 없는 첫 화면 확인 | 미실행 |
| AC5 완료 취소 | 완료된 항목의 완료 표시를 다시 누른다. | 해당 항목이 미완료 상태로 돌아간다. | 전환 전후 화면 비교 | 미실행 |

## 9. 위험 및 제약

- 메모리 저장이므로 앱을 종료하면 데이터가 사라진다.
- 제목의 최대 길이와 공백 처리 기준은 구현 전에 정해야 한다.
- 완료 상태를 바꿀 때 다른 항목까지 함께 바뀌지 않도록 항목 식별자를 기준으로 처리해야 한다.
- 실제 실행과 AC 검증은 아직 진행하지 않았으므로 통과했다고 표시하지 않는다.

## 10. 10주차 첫 작업

**첫 작업:** Flutter에서 DailyTodo의 첫 화면을 만들고, 제목 입력란과 추가 버튼을 배치한다.

1. `Scaffold`와 `AppBar`로 기본 화면을 구성한다.
2. 제목 입력란과 추가 버튼을 배치한다.
3. `id`, `title`, `isDone` 구조를 기준으로 메모리 목록을 준비한다.
4. 정상 제목 추가(AC1)와 빈 제목 거절(AC2)을 먼저 구현하고 실행으로 확인한다.

- **예상 프로젝트 위치:** 기존 개인 Flutter 작업 폴더 안의 DailyTodo 프로젝트
- **실행 명령:** 프로젝트 폴더에서 `flutter run`
- **현재 코드 상태:** 이 문서 작성 시점에 DailyTodo 구현 코드 위치와 실행 결과는 확인되지 않았으므로 구현 전으로 기록한다.
- **미확인 기술:** 제목 최대 길이, 공백 처리 기준, 사용할 상태 관리 방식
